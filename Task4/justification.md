## Обоснование конфигурации
1. Группа безопасности контролирует входящий трафик на виртуальные машины: доступ по SSH ограничен вашим IP-диапазоном, а HTTP открыт для базового тестирования.  
2. VPC и подсети обеспечивают изоляцию и управляемую маршрутизацию трафика. Публичная подсеть служит для доступа из внешней сети, а приватная — по NAT для выхода во внешний мир без входящих соединений.  
3. Виртуальная машина EC2 размещена в публичной подсети, дополнительные данные хранятся на отдельном диске EBS, что разделяет вычислительные ресурсы и хранение данных.  
4. Интернет-шлюз и маршрутизация публичной подсети обеспечивают двунаправленный трафик для виртуальных машин. NAT-гейтвей позволяет приватным подсетям выходить в интернет без прямого доступа извне.  
5. Использование подхода Infrastructure as Code повышает воспроизводимость и упрощает развертывание окружений — изменения проходят этап планирования и проверки.  
6. Все ресурсы снабжены тегами, что облегчает управление и учёт затрат на облако.  
7. Для хранения неструктурированных или сырых данных используется объектное хранилище S3, обеспечивающее удобство загрузки и экономичное долговременное хранение.  

## Применение
1. Архитектура позволяет гибко масштабироваться, добавляя новые подсети и сервисы без изменения основной логики.
2. Такая конфигурация подходит для развертывания решений по созданию витрин данных и аналитических сервисов.  
3. Пайплайны данных могут загружать сырые наборы из S3 и записывать обработанные данные в облачное хранилище.
