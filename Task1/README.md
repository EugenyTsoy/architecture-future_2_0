## 1.2 Описание проблемных мест
| Компонент | Проблемы и недостатки |
|-----------|----------------|
| Интеграционная платформа | - Нет контейнера и шины надежного обмена сообщениями, в следствии чего есть вероятность из потери<br>- Синхронная маршрутизация сообщений создает сильную связанность между компонентами системы<br>- При добавлении новых источников требуется внесение изменени во всех настройках маршрутизации<br/>\- Нет контейнера и шины надежного обмена сообщениями<br/>\- Сложность миграции правил ФЛК из легаси<br/>\- Нет стриминга для оперативного обновления данных<br/> |
| DWH | - Неудовлетворительная производительность чтения при выполнении аналитических запросов<br>- Ограничения по объёму хранения данных<br>- Работа только со структурированными данными<br>- Отсутствие средств защиты от несанкционированного распространения конфиденциальной информации<br>- Проблемы с разграничением доступа<br>- Высокие операционные расходы на покупку лицензий<br>- Пользователи не имеют ограничений к данным<br />\- Медленное построение аналитики<br />- Нет разграничения доступа и защиты PII |
| Клиенсткий интерфейс оператора | - Сложность обучения работе с языком PowerBuilder и наймов квалифицированных специалистов<br>- Недоступно для бизнес-пользователей |
| BI-система |- Зависимость от экосистемы Microsoft. Power BI лучше интегрируется с другими продуктами Microsoft и имеет ограниченную совместимость с некоторыми инструментами<br>- Ограничение на одновременное получение данных при обучении моделей ИИ<br>- Сложности с обработкой сложных связей между таблицами. Для поиска решений в этом случае требуется хорошо разбираться в синтаксисе DAX |


## 1.3 Приоритизация проблем по методу MoSCoW
### Must have (Критически важные)
#### Интеграционная платформа на Apache Camel
- Обоснование: Недостаточная производительность и сложность поддержки
- Риски: Потеря данных, единая точка отказа
- Влияние на бизнес: Критическое (прерывание работы компании)
#### DWH на RDBMS / Delta Lake + разграничение прав доступа
- Обоснование: Сложность встраивания новых источников данных. Производительность, защита данных, гибкость аналитики
- Риски: Подключение нового источника данных или изменение структуры хранения, влечёт за собой масштабные доработки ETL-процессов. Низкая проидительности при выполнении аналитических запросов.
- Влияние на бизнес: Критическое (прерывание бизнес-процессов), соблюдение регуляторных требований, time-to-market
#### Разграничение прав доступа к данным 
- Обоснование: Игнорируются политики защиты и безопасности данных
- Риски: Утечка данных, несанкционированный доступ
- Влияние на бизнес: Критическое (репутационные и финансовые потери)

**Интеграционная платформа с ESB + FLK Service + Streaming**

- Обоснование: миграция ФЛК, поддержка реального времени, снижение связанности
- Влияние на бизнес: критическое — безопасный и быстрый обмен данными между клиниками, ИИ и финтех

### Should have (Важные)
#### Доступность данных для бизнес-пользователей
- Обоснование: Бизнес-пользователи должны иметь возможность быстро получать доступ к необходимым данным
- Риски: Потеря конкурентного преимущества
- Влияние на бизнес: Значительное (снижение эффективности)
- Документирование и версионирование правил FLK
- Автоматизация пайплайнов стриминга данных
#### Отказ от PowerBuilder
- Обоснование: Сложность поддержки и обучение
- Риски: Потеря квалифицированных специалистов
- Влияние на бизнес: Значительное (снижение эффективности)
### Could have (Желательные)
#### Data Governance
- Обоснование: Нужно обеспечить контроль над данными и их безопасностью
- Риски: Сложность внедрения и поддержки. Требуют организационной подготовки.
- Влияние на бизнес: Среднее (выстраиваемая модель оторвана от бизнес-задач)
- Расширенный мониторинг событий и SLA на стриминг
### Won't have (Не приоритетные)
#### Data Intelligence
- Обоснование: Помогает управлять данными, обеспечивать их качество, целостность и безопасность
- Риски: Требует дополнительных операционных затрат
- Влияние на бизнес: Низкое (не влияет на бизнес-процессы)
